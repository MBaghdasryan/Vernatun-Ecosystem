# ImTun: безопасное dev-подключение и приёмка телефонов

Дата: 2026-10-26.

**Статус: PARTIAL / требуется доступ к физическим Android и iPhone.**
Сборка bundle, тесты адаптеров и браузерное preview не считаются физической
проверкой телефона. Реальный вход и матрица разделов на телефонах не заявляются.

Пользователь подтвердил отсутствие физического тестового стенда и выбрал
оставить проверку телефонов незавершённой. Программная часть завершена в этом
согласованном объёме; физическая приёмка отложена, а не засчитана как успешная.
Expo Go открывает приложение на телефоне через QR из Preview Replit; наличие
preview само по себе не означает, что проверены native-сценарии Android/iOS.
Инструкция Replit: https://docs.replit.com/build/mobile-preview-testing.

## Реализовано

- В development web использует свой origin и путь
  `/__imtun_dev_api/api/...`. Metro передаёт только эти запросы локальному
  artifact router (`127.0.0.1:80`), затем существующему API `/api`.
  Случайно унаследованный `EXPO_PUBLIC_API_URL` production не используется.
- Native development получает `EXPO_PUBLIC_DEV_API_URL` из development workflow
  (`REPLIT_DEV_DOMAIN`). Отсутствие адреса приводит к явной ошибке, не к
  автоматическому переключению на production.
- Proxy не принимает URL upstream из HTTP-запроса или из настройки release API.
  Проверяет Host/Origin/Fetch Metadata, не следует redirect, не кэширует ответы.
  Передаёт cookie и CSRF header; после проверки browser origin не передаёт его
  локальному API. Авторизация и проверка CSRF на API остаются прежними.
- Production CORS, production CSRF и разрешения документов не менялись.
  Release использует прежние `EXPO_PUBLIC_API_URL` / `EXPO_PUBLIC_DOMAIN`;
  Metro bridge отсутствует в production сервере.
- Native документ загружается существующим `downloadResidentDocument`, который
  использует общий authenticated transport и серверную document authorization.
  Нет публичных storage URL, bearer/session в URL или обходного файлового fetch.
- Вместо сообщения «недоступно» кнопка «Открыть / сохранить» вызывает системное
  меню для приватного локального файла. Ошибки показываются на всех платформах.
  Title документа не используется как путь; MIME берётся из ответа API.
  Уход со списка/смена контекста прерывает ещё не завершённую загрузку.
- iOS завершение меню и ошибки записи/открытия удаляют временный файл.
  Android оставляет успешно переданный файл в приватном cache до следующего
  холодного запуска: chooser может завершиться раньше чтения content URI
  принимающим приложением. Остатки незавершённого открытия также удаляются при
  следующем запуске. Это не постоянный offline-каталог документов.
  Пользователь явно экспортирует файл через системное меню; копии, сохранённые
  им в другом приложении, уже не управляются ImTun.

## Что проверено здесь

| Проверка | Результат |
| --- | --- |
| TypeScript ImTun | PASS |
| `test:dev-proxy` | PASS: cookies/CSRF, локальный upstream, чужие origin/host, cross-site, запрет redirects |
| `test:private-documents` | 4 PASS: iOS cleanup, Android URI lifetime/cold-start cleanup, denied/unavailable/abort, write/share errors |
| `--resident-superapp-only` | 11 PASS в новой изолированной схеме `vernatun_test` |
| `--imtun-only` | 4 PASS: owner/renter/family, границы финансов, смена контекста, просроченное назначение |
| Expo export iOS + Android | PASS: обе Hermes-сборки; это не native build/install и не запуск на устройстве |
| HTTPS preview bridge | `/__imtun_dev_api/api/auth/session` отвечает 200, в том числе с корректным preview Origin |
| Чужой origin через Metro | Заблокирован самим Expo до proxy; Expo возвращает 500, данные API не выдаются. Собственный middleware отдельно проверен на 403 |

API-тесты создают и удаляют собственные случайные схемы в тестовой базе, не
сбрасывают production-аккаунты. Не вызывались реальные PSP, email-приглашения
или устройства доступа здания. Автотесты используют только искусственную
регистрацию установки, без push-провайдера.

## Матрица физической приёмки — ещё НЕ выполнена

Нужны управляемые тестовые Android и iPhone с совместимым Expo Go либо
тестовой сборкой, а также изолированный backend с синтетическими аккаунтами
owner/renter/family. Не присылайте пароли или session cookies в переписку.

На **каждом** устройстве и для **каждого** из трёх контекстов:

1. Холодный запуск → вход тестового пользователя → выбор квартиры; повторный
   запуск сохраняет только допустимую сессию. Ошибка входа не открывает разделы.
2. Переключение между двумя разрешёнными контекстами → старые записи/права
   не отображаются, данные соответствуют новой квартире.
3. Автомобиль: создать → обновить экран → изменить → удалить. Данные чужого
   пользователя недоступны.
4. Профиль: изменить допустимые поля/приватность → перезапустить → значения
   сохранены; подтверждённый email не подменяется.
5. Счётчики: список и история → допустимое показание → обновление списка;
   ошибка/повтор не создаёт незаметный дубль. Family видит только разрешённое.
6. Документы: разрешённый PDF → системное меню → открыть/сохранить и проверить
   содержимое. Проверить отмену меню, запрет чужого документа, потерю сети,
   смену контекста во время загрузки. На Android проверить чтение в приложении-
   получателе и удаление cache после холодного запуска.
7. Отзыв **тестовой установки ImTun** (не устройства управления зданием):
   связанная сессия получает отказ, другая тестовая сессия остаётся рабочей;
   возврат из background/перезапуск не восстанавливает отозванный доступ.

Фиксировать модель/OS/версию сборки, роль и результат каждого шага без паролей,
токенов и персональных данных. До появления этих результатов физическая
приёмка остаётся открытой. Общая проверка UI в signed-in mobile preview
в этой итерации также не заявляется.
