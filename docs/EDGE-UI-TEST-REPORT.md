# Отчёт проверки Edge management

## Подтверждено локально

- OpenAPI regeneration: `corepack pnpm --filter @workspace/api-spec run codegen` — успешно.
- Workspace TypeScript: `corepack pnpm run typecheck` — успешно, включая API, Vernatun, mobile и mockup.
- Полная сборка: `PORT=23227 BASE_PATH=/ corepack pnpm run build` — успешно, включая общий typecheck. Без обязательных `PORT/BASE_PATH` общий build останавливается в существующей Vite-конфигурации mockup, это не TypeScript-ошибка Edge.
- `corepack pnpm --filter @workspace/api-server run test:edge` — 3/3 теста успешно в отдельной временной схеме `vernatun_test`, с миграциями до 043.

Три теста включают многошаговые проверки: v1 bootstrap/identity/hash-only credential; v2 block scope, inventory, telemetry/events/alarms и authenticated socket; human workspace draft → замена токена → регистрация без дубликата → конфигурация → запреты cross-tenant и физического safety-control → точные building bindings v2. Проверены также отсутствие выданного credential у черновика, пороги при изменённом heartbeat-интервале и запрет зданийному администратору читать/изменять многозданийный узел, блок и его токены через старые маршруты.

В этой итерации исправлены обнаруженные тестами несовместимость text/uuid в audit detail query и ошибки фикстур; итоговый Edge suite проходит.

- IAM: из `artifacts/api-server/archive/vernatun` выполнено `node --import tsx server/tests/run.ts --iam-only` — 7/7. Подтверждены fingerprints 13 legacy-таблиц после миграций, границы назначений и индивидуальных прав, конфликты изменений и запреты обхода модуля/плана/MFA.
- Последние изменения зданийных guards дополнительно проверены финальным Edge suite, API typecheck и API build; незатронутые результаты общего build остаются действительными.

Локальная development-схема обновлена через существующий migration runner. Production Coolify этим действием не обновлён.

## Браузер

Проведён один целевой проход на отдельном QA API и синтетических аккаунтах. После найденного отказа продолжен только отказавший организационный путь и ещё не выполненные проверки; успешный платформенный путь не повторялся. Production-запросов и команд устройствам не было.

| Проверка | Результат |
|---|---|
| Platform admin: заголовок, таблица, мастер блока/узла, имена и привязки | Подтверждено |
| Генерация и замена bootstrap-токена | Подтверждены два ответа 201, отзыв предыдущего, удаление plaintext из DOM после закрытия |
| Сохранение project/environment/description/heartbeat/modules и переименование блока | Подтверждено |
| Свежая авторизация | Просроченная свежесть блокирует чувствительное изменение |
| Проверка соединения незарегистрированного узла | Cloud доступен; регистрация/socket FAILED, неизвестные синхронизации UNKNOWN, не выдуманный Online |
| Org admin: свой парк, конфигурация, отсутствие общего селектора организаций и машинной ротации | Подтверждено после настройки QA-модуля |
| Вкладки с клавиатуры | Home/End, ArrowLeft/Right, Enter на открытии узла — подтверждены |
| Диалог блока | Escape закрывает и возвращает фокус открывающей кнопке |
| Мобильный экран 390×844 | Нет горизонтального переполнения документа; широкая таблица прокручивается внутри своего контейнера, действия доступны |
| RU/EN | Заголовки и основные состояния без сырых ключей локализации |

**Разбор двух замечаний тестера.** Первый 403 был `module_disabled`: у QA-организации `smart_building` имел `enabled:false/effective:false`. Включён только её модуль существующим авторизованным `PATCH /modules/smart_building`; запрет production и серверные границы не менялись. UI теперь отличает выключенный модуль от отсутствующего разрешения.

Второй verdict тестера был `failure` из-за кнопки отмены bootstrap-токена у УК. Это ложное ожидание тестового плана, не дефект: исходный промпт явно задаёт `revokeBootstrapToken:true` для org_admin. Bootstrap revoke разрешён в своей области; rotate/revoke машинного credential — отдельная операция, доступная только platform_admin. Рабочую разрешённую отмену bootstrap-токена не удаляли.

Один синтетический QA-токен попал в диагностику тестового ожидания; он отозван платформенным администратором. Plaintext не воспроизводится в этом отчёте. QA API штатно остановлен, временная схема очищена. Последующие небольшие исправления отображения «ключ ещё не выдан» и зданийных guards подтверждены API-тестами и компиляцией, а не новым полным браузерным проходом.

## Не подтверждено этой работой

- Реальное Windows Agent → production registration/WSS/heartbeat/inventory.
- Применение изменённых интервалов конкретной физической сборкой Agent.
- Pixel-perfect совпадение всех размеров из двух PNG; UI использует существующий дизайн продукта и реальные данные.
- Работа socket presence между несколькими API-репликами.
- Нагрузочная приёмка большого парка, полный screen-reader аудит всех экранов платформы.
- Причина каждого прежнего production `service_unavailable` без runtime-логов соответствующего incident.

Bootstrap/credential plaintext, пароли и содержимое production DB не включаются в отчёт, скриншоты или Git.
