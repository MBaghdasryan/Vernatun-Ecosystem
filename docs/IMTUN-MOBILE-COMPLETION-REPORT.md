# ImTun — отчёт о реализации mobile master prompt

## Итог

**Статус всего master prompt: PARTIAL, не завершён.**

Обновлено существующее Expo-приложение ImTun. Новый продукт или отдельная
авторизация не создавались. Рабочие resident API, финансовые записи,
разрешения, голосования и Edge-команды остаются серверными источниками истины.
Визуальные референсы использованы для иерархии и оформления, но полная
постраничная pixel/parity-приёмка трёх ролей ещё не проведена.

Начальный разбор всех 65 пунктов:
[IMTUN-MOBILE-GAP-AUDIT.md](IMTUN-MOBILE-GAP-AUDIT.md). Это снимок состояния
**до** данного изменения, а не список уже закрытых пунктов.

## Что реализовано в этом изменении

- Нижняя навигация теперь различается по активной роли и серверным правам:
  - **Собственник:** Дом → Финансы → Доступ (если разрешён) → Заявки → Профиль.
  - **Арендатор:** Дом → Доступ (если разрешён) → Проблемы → Взнос и платежи
    (если разрешены) → Ещё.
  - **Член семьи:** Дом → Доступ (если разрешён) → Заявки → Чат → Ещё.
  Недоступные разделы убираются из навигации. В «Ещё» остаётся ссылка на профиль,
  настройки и только разделы, разрешённые для активного контекста.
- Главная страница с разным порядком блоков для собственника, арендатора и
  члена семьи. Назначение роли меняет композицию, но не выдаёт разрешения.
  Денежные блоки отображаются только при наличии сумм, разрешённых сервером.
- Смена объекта через профиль, с доступом к переключению из главной.
  При смене назначения очищается кеш запросов предыдущего контекста.
- Отдельный экран начислений: реальные остатки, просрочка, оплата за год,
  существующие счета, платежные intent и ссылки на счётчики и финансы дома.
  Успешный возврат из браузера не подтверждает оплату.
- Главная страница сообщества с вкладками объявлений, чатов, обсуждений
  и голосований. Сохранены существующие независимые процессы заявки
  из обсуждения и рассматриваемого предложения в повестку.
- Член семьи по умолчанию попадает в чат, остальные роли — в объявления.
  Ролевые подписи и порядок разделов не меняют серверные разрешения.
- В заявках: фильтры «Все / Активные / Завершённые», счётчики, отдельная
  карточка с историей, выбор фотографии из галереи или камеры.
  Создание заявки остаётся явным действием пользователя; распознавание фото
  не имитируется.
- Доступ к устройствам активного здания через существующий resident API.
  Действия получаются с сервера, без обращения браузера к Edge/ThingsBoard.
  Отслеживание результата команды через `/api/me/edge-commands/:commandId`;
  повторное нажатие блокируется до терминального состояния.
  ACKNOWLEDGED не отображается как «Открыто».
- Для другого здания требуется сначала выбрать соответствующий разрешённый
  контекст. Экран не выдаёт доступ к устройствам всех зданий автоматически.
- Общая палитра и переключение light/dark/system подключены к основным вкладкам
  и resident-модулям: финансы, объявления, документы, счётчики, семейные формы,
  переписка, бронирования, объявления недвижимости, поддержка и настройки.
- Новые основные экраны, фильтры заявок и сообщения локальной безопасности
  имеют HY/RU/EN-тексты. Это не означает завершения языкового аудита приложения.
- Необязательное сохранение подсказок аккаунтов на устройстве: только имя
  и email, до пяти записей, удаление и выбор email. По умолчанию выключено.
  Пароли, токены, разрешения и серверная сессия в эти подсказки не попадают.
  При выборе другого аккаунта очищаются введённые пароль и код.
- Необязательная локальная блокировка для нативного приложения: PIN,
  device-only SecureStore, ограничение попыток, привязка к пользователю,
  биометрия через системный диалог при доступном оборудовании.
  Это не замена паролю, MFA или серверной авторизации.
  В web-версии небезопасная имитация нативного PIN не включается.
- Добавлены нативные плагины и описания разрешений для камеры, SecureStore
  и локальной биометрии. Их окончательная проверка требует нативной сборки.
- В «Ещё» для собственника, арендатора и члена семьи добавлен раздел «Устройства
  и интеграции». Он показывает серверные статусы платежей, коммунальных услуг,
  доступа, BLE, домофона, камер, AI и push. Для камеры и домофона предусмотрены
  пустые области просмотра; поток и вызов не имитируются. Раздел не отправляет
  команды. Переход к доступу ведёт только в существующий экран с серверными
  разрешениями.
- Главная больше не показывает вечный пустой skeleton, когда активный дом не
  выбран. Она объясняет отсутствие контекста и ведёт в выбор дома. В профиле
  можно выбрать дом даже при единственном доступном контексте, если активный
  контекст ещё не установлен.

## Подтверждённые проверки

| Проверка | Результат и границы |
|---|---|
| `corepack pnpm run typecheck` | PASS во всех workspace-проектах после базовой сборки |
| `corepack pnpm --filter @workspace/imtun-mobile run typecheck` | PASS после ролевой навигации и отдельной вкладки доступа |
| Тесты resident-security | 12 PASS: whitelist аккаунтов, отсутствие пароля/PIN в открытом хранилище, пользовательский scope, throttling, повреждённое хранилище, биометрия |
| Тесты private-document | 4 PASS на моделях iOS/Android: авторизованный transport и удаление временных приватных файлов |
| Тест dev-api-proxy | 1 PASS: origin, cookies/CSRF, запрет чужих redirects |
| Общий результат трёх наборов | 17 PASS, 0 FAIL |
| Expo workflow | Replit Expo CLI вошёл в managed-сессию; Metro запустил Android bundle и обслуживает preview |
| Статус соединения | Development API и Expo status endpoint отвечают; серверной ошибки запуска не найдено. Уведомление Expo Go на физическом Android здесь воспроизвести нельзя |
| Публичный экран, 390×844 | Снимок входа успешно загружен, без crash/red screen |

Тесты нативных адаптеров используют заглушки ОС. Они не подтверждают поведение
Face ID, Android BiometricPrompt, SecureStore или камеры на физическом телефоне.

**Не проверено в этом ходе:** авторизованные экраны owner/renter/family в браузере,
полная матрица размеров и screen reader, нативные Android/iPhone.
Снимок экрана входа не является приёмкой защищённых экранов.
Ролевые вкладки, начальная вкладка чата семьи и путь «Ещё → Профиль» проверены
кодом и typecheck, но не нажимались в авторизованном UI.

В контейнере выводится предупреждение об отсутствующей библиотеке для отдельного
React Native DevTools. Оно не остановило вход Replit Expo CLI, сборку Android
bundle или Metro. Уведомление «Cannot connect to Expo CLI…» на приложенном
физическом Android-снимке этим не подтверждено как исправленное: после перезапуска
пользователю нужно открыть актуальную QR-сессию, а соединение телефона проверить
на самом устройстве.

## Что ещё не завершено внутри приложения

1. Полный monthly-ledger drill-down, расширенные поиск/детали истории платежей,
   отдельная мобильная форма банковской квитанции и все финансовые
   загрузки/детализации из master prompt.
2. Полный rich messenger: не все вложения и расширенные состояния общения
   имеют интерфейс референсов. Существующие текстовые чаты сохранены.
3. Полное соответствие карточек гостевого пропуска референсам: QR/PIN,
   продление и sharing нельзя считать завершёнными только по форме
   создания/отзыва записи пропуска.
4. Отдельный контракт и интерфейс краткосрочного проживания; его активация
   и истечение не создавались поверх неподтверждённой серверной модели.
5. Общий языковой аудит: например, вход, часть технических/ошибочных сообщений
   и некоторые старые подписи требуют проверки. Темизация кода не равна
   визуальной приёмке всех экранов в обеих темах.
6. Полная офлайн-модель чтения, расширенная пагинация и производительность
   длинных списков. Нельзя выдавать локальный черновик заявки за полноценный
   офлайн-режим; финансовые и физические команды автоматически не повторяются.
7. Совместная браузерная приёмка семейных/арендных разрешений, делегирования
   плательщика, обсуждений, объявлений недвижимости и просмотров с новым UI.
8. Полная покомпонентная сверка всех storyboard-экранов для трёх ролей,
   touch targets, keyboard/focus, screen reader, большие шрифты и размеры
   360/390/768/1024/1440.

## Внешние подключения и реальные устройства

Экран «Устройства и интеграции» — только оболочка и отображение server status.
Он не означает готовность пользовательских потоков камеры, домофона, BLE,
AI, push или провайдеров.

Не объявлены готовыми: платежные провайдеры и их live-приёмка, сохранённые
карты/мандаты автоплатежей, SMS-подтверждение, push delivery, AI/vision,
BLE, домофоны, камеры и непротестированные аппаратные адаптеры.

История/заявка по фото не означает распознавание изображения. Регистрация
push installation не означает доставку push. Кнопка платежа не означает
готовность договора/merchant. Доступное действие Edge не означает
подтверждённое физическое открытие.

Тест шлагбаума на реальном Windows Edge в этом изменении не возобновлялся.
Физические команды не отправлялись.

## Production

Production, существующие пароли пользователей, интеграции Resend, Edge-регистрация
и миграции не изменялись. Никакая production-выкладка не выполнена.
Миграция 048 не применялась этим изменением.

Следующая приёмка: авторизованные пути owner/renter/family на тестовых данных,
затем нативная сборка Android/iOS и аппаратные/платёжные подключения
по отдельному согласованному сценарию.
