# ImTun — восстановление и границы готовности

Дата проверки: 6 октября 2026 года.

## Результат восстановления

По уточнённому запросу ImTun восстановлен **внутри Vernatun Web, аналогично HAYAT**. Expo-артефакт не создавался. Это адаптивный веб-кабинет жильца с общей серверной сессией и общей базой Vernatun, а не нативное приложение или готовый релиз в магазинах.

Приложенный `IMTUN_1791287558913.md` описывает историческое состояние от 30 сентября. Этот документ — отдельная актуальная сверка с предоставленным ZIP и текущим проектом. Исходные вложения не изменены.

### Восстановлено непосредственно из ZIP

Все четыре файла скопированы без изменений:

- `src/imtun/ResidentApp.tsx` — оболочка кабинета жильца.
- `src/imtun/resident.css` — исходные адаптивные стили.
- `src/imtun/i18n.ts` — исходные тексты HY/RU/EN.
- `src/imtun/config.ts` — бренд, доступность разделов и описательные build profiles.

Используется существующий `public/assets/imtun-original.png`. Логотип, изображения, тексты и дизайн не заменялись.

### Восстановлено подключение к общей платформе

- Оболочка ImTun подключена к авторизованному порталу для собственника, арендатора и семьи.
- Сохранены существующие вход, контексты, разрешения, модули, настройки языка/валюты и выход.
- Общие экраны заявок, финансов, документов, счётчиков, объявлений, собраний, пропусков, делегирования, аренды и безопасности используются без создания второго бизнес-движка.
- В ответ существующей сессии добавлены серверные подписи `building_name` и `unit_number`, отсутствовавшие в текущем серверном исходнике. Они получаются из назначения и существующих таблиц; никаких новых прав не дают.
- Выбор контекста показывает конкретные дом и квартиру, если они есть.

Новых endpoints, ролей, разрешений, сущностей или миграций основной базы не добавлено. Основные аккаунты и бизнес-записи не создавались и не менялись. Тестовые назначения и записи использовались только в изолированной тестовой базе/схеме с последующим удалением.

## Маршруты

| Адрес | Назначение |
|---|---|
| `/login` | Общий вход Vernatun |
| `/imtun/owner` | Главная собственника |
| `/imtun/renter` | Главная арендатора |
| `/imtun/family` | Главная семьи |
| `/imtun/payments` | Начисления и существующие финансовые операции |
| `/imtun/requests?requestId=<uuid>` | Заявки и выбранная карточка |
| `/imtun/meters` | Показания счётчиков |
| `/imtun/announcements` | Объявления |
| `/imtun/documents` | Документы |
| `/imtun/access` | Пропуска |
| `/imtun/meetings` | Собрания |
| `/imtun/delegations` | Действующее делегирование прав |
| `/imtun/leases` | Договор аренды |
| `/imtun/notifications` | Внутренние уведомления |

Отсутствие раздела в интерфейсе не заменяет серверную проверку. Прямой адрес недоступного раздела не должен показывать его данные.

## Что сделано и что ещё отсутствует

«Подключено» означает использование существующего рабочего кода и API. Все операции записи через новый интерфейс в этом сеансе не прогонялись на пользовательской базе.

| Область | Текущий статус | Ограничение / что ещё не сделано |
|---|---|---|
| Кабинеты собственника, арендатора, семьи | Восстановлено | Один общий серверный источник полномочий; права разных контекстов не объединяются |
| Главная | Восстановлено | Реальные API-данные, приветствие, квартира, быстрые действия, заявки, объявления, собрания, финансовый итог при наличии права |
| Загрузка и сетевой статус | Восстановлено | Ошибки и повторная загрузка есть; индикатор отсутствия сети не является офлайн-кэшем |
| Финансы собственника/арендатора | Подключено | Счета ограничены текущей квартирой и `payer_user_id`; арендатор не получает автоматически долги собственника |
| Ограничения семьи | Восстановлено | Финансы и управление делегированием не выдаются по умолчанию |
| Заявки | Подключено к Workflow | Тема, описание, фото, сообщения, история и существующие переходы; нет новых категорий, предпочтительного контакта и согласования/переноса визита |
| Счётчики | Подключено | Используются существующие серверные операции |
| Документы и защищённые скачивания | Подключено | Сохранены исходные бизнес-проверки доступа и работа общего хранилища; отсутствующие ранее байты документов этот ZIP не содержит |
| Объявления | Подключено | Нет нового расширенного таргетирования по этажу/подъезду |
| Собрания и голосование | Подключено | Только существующие возможности backend; полный юридический процесс голосования и новые материалы не добавлены |
| Пропуска | Подключено | Не означает подключение физического контроллера двери |
| Делегирование семье | Частично | Используется существующий механизм; полного нового приглашения/принятия и повторной аутентификации чувствительных действий нет |
| Договор арендатора и срок доступа | Подключено | Показываются только доступные данные; истёкшее назначение не даёт доступа |
| Внутренние уведомления | Частично | Общий список и отметка прочтения есть; исторически упомянутые ссылки из уведомлений на заявку в текущем общем компоненте отсутствуют |
| Cross-context deep links | Не реализовано полностью | Ссылка не переключает самостоятельно на другой защищённый контекст |
| Языки и валюты | Восстановлено | HY/RU/EN и AMD/RUB/USD; тексты бизнес-записей автоматически не переводятся |
| Контакты и правовые ссылки | Частично | Поля предусмотрены в конфигурации, но отсутствующие значения не выдумываются |
| Branding | Частично | Исходный логотип, runtime-цвет и метаданные; полноценного UI управления брендом и API всех полей нет |
| Аналитика | Отключённый адаптер | Настоящий провайдер и полный набор событий не подключены |
| Онлайн-оплата | Не подключена | Нет эквайринга и серверного подтверждения провайдера; кнопка оплаты ведёт к начислениям, а не имитирует успешную транзакцию |
| SMS/email-доставка | Не подключена | Восстановление формы не подключает внешнюю доставку |
| Push | Не подключён | Нет нативного push-провайдера |
| PWA/offline cache | Не реализовано | Нет service worker и полного офлайн-режима |
| Native iOS/Android, Expo, биометрия | Не восстановлено и не создавалось | В ZIP нет этих исходников; выбрана веб-версия |
| Premium branded store builds | Не реализовано | Описательные build profiles не являются подписанными сборками |
| Независимые контексты вкладок | Не реализовано | Активный контекст хранится в общей серверной сессии |

## Что не было предоставлено

ZIP содержит только четыре перечисленных веб-файла. В нём нет:

- нативных проектов iOS/Android, Expo-конфигурации, APK/IPA;
- исторических `scripts/imtun-dev.cjs` и `scripts/imtun-qa.cjs`;
- исторических скриншотов `docs/imtun-preview/`;
- исходников исторических изменений общего компонента уведомлений;
- новых серверных бизнес-модулей, файлов пользовательских документов или резервной копии их байтов.

Отдельный сервер ImTun не нужен: используются существующие процессы API Server и Vernatun Web.

## Текущие проверки

| Проверка | Результат |
|---|---|
| Сравнение всех четырёх файлов с ZIP | Идентичны |
| TypeScript, Vernatun Web | Пройдено |
| TypeScript, API Server | Пройдено |
| Производственная сборка Vite | Пройдено |
| Новые изолированные API-тесты ImTun | 4 из 4 пройдены |
| Браузерная проверка защищённых экранов | Пройдена для собственника, арендатора и семьи: desktop 1440×900 и mobile 390×844 |

В браузере проверены:

- Главная собственника на компьютере и телефоне: логотип, подписи дома/квартиры, реальные баланс, заявка и объявление. Наложений и горизонтального переполнения страницы не обнаружено.
- Открытие существующей заявки по `requestId`, её история и возврат браузерной кнопкой Back.
- Начисления собственника и просмотр профиля/безопасности без изменения настроек. Успешный платёж не имитировался.
- Главная арендатора: назначенная квартира, срок доступа, начисления и переход к договору. В текущих данных список договоров пуст; содержание договора поэтому не проверено и не создавалось ради теста.
- Главная семьи без финансовых и делегирующих действий. Прямой `/imtun/payments` показывает отказ в доступе без финансовых данных.

JavaScript-ошибок и ошибочных API-запросов в этом прогоне не обнаружено. В общем экране безопасности Chromium показал неблокирующее предупреждение об атрибутах формы пароля. Бизнес-записи, пароли, роли, языковые/валютные настройки при браузерной проверке не менялись.

Текущие API-тесты проверяют:

1. Подписи дома и квартиры соответствуют действующему контексту жильца.
2. Семья не может получить счета или управлять делегированием.
3. Счета собственника и арендатора ограничены квартирой и плательщиком.
4. Переключение собственника на назначение арендатора другой квартиры не объединяет права и scopes; истёкшее назначение отклоняется.

Из каталога `artifacts/api-server/archive/vernatun`:

```sh
node --import tsx server/tests/run.ts --imtun-only
```

Исторические «32/32», «20/20» и браузерные проверки всех ширин из приложенного MD не выдаются за текущий прогон. Ручная проверка VoiceOver/TalkBack, большого системного шрифта и реальных мобильных устройств в этом восстановлении не выполнялась.
