# Phase 3 — обслуживание и жизненный цикл ImTun

Дата: 6 октября 2026 года.

## Реализованный объём

### Обслуживание оборудования → существующий WorkOrder

- Планы: однократно, ежедневно, еженедельно, ежемесячно, ежеквартально, раз в полгода, ежегодно, свой интервал в днях.
- Категория, приоритет, инструкции, чек-лист, начальная дата; активность и автоматическая генерация включаются явно.
- Даты считаются от исходной даты в UTC: 31 января → 28 февраля → 31 марта, без накопленного сдвига.
- План → событие → настоящая заявка → один WorkOrder. Для общедомового оборудования используются building scope и системный автор, без фиктивной квартиры и сотрудника.
- Неназначенный WorkOrder имеет состояние `queued`. Диспетчер/управляющий назначает допустимого техника; чек-лист плана сохраняется.
- Техник принимает и выполняет работу в прежнем workflow. Для отчёта обслуживания требуется завершённый чек-лист и хотя бы одна приватная фотография.
- Управляющий может вернуть работу с причиной либо проверить и закрыть её. Невозможное подтверждение жителем общедомовой работы не требуется.
- История оборудования содержит события, исполнителя, отчёт, чек-лист, ссылки на заявку и метаданные фото.
- Уникальность plan/cycle и блокировка плана предотвращают конкурентные дубли. Ручная генерация принимает cycleNo: повтор старого цикла возвращает его событие, даже после закрытия.
- Автоматическая генерация встроена в существующий managed job и проверяет подписку/модули. На один план допускается только одно незакрытое событие.
- После проверки рассчитывается следующий цикл. Завершённые однократные планы повторно не активируются.
- Прежний endpoint «complete» больше не закрывает план без WorkOrder: возвращает `work_order_verification_required`.
- Восстановленные планы по умолчанию неактивны. Исторически завершённые планы остаются read-only.

### Делегирование

- Email, необязательный контактный телефон, ограниченные разрешения, срок, отдельное приглашение и отдельный family assignment после принятия.
- Финансы, управление пользователями, право собственности и управление договорами не входят в разрешённый набор.
- Владелец видит состояние, меняет срок с проверкой версии, отзывает доступ и повторно отправляет только ожидающее приглашение.
- Повторная отправка меняет token hash; прежняя ссылка перестаёт работать.
- Создание, изменение срока, повторная отправка и отзыв требуют авторизации не старше пяти минут. Повторная проверка использует пароль и настроенный MFA.
- Интерфейс очищает пароль/MFA и требует явной повторной отправки действия после reauthentication; автоматического повторения нет.
- Существующий EmailProvider и учёт delivery evidence сохранены.

### Визиты

- Визит может предложить диспетчер или назначенный техник.
- Житель подтверждает время либо запрашивает другое, в том числе после подтверждения.
- Запрос другого времени требует причины, может содержать полную пару будущих дат длительностью до суток.
- Предыдущее предложение сохраняется как отменённое; причина, предложенное окно и действия отражаются в истории.
- Повтор операции с тем же ключом не добавляет вторую запись.

### Уведомления и контексты

- Список относится только к текущему пользователю, но может включать уведомления для его других assignments.
- Backend заново определяет допустимые назначения, учитывая организацию, здание, помещение, принадлежность заявки, исполнителя, срок доступа и модули.
- Для другого контекста интерфейс сначала требует подтверждения. Права разных assignments не объединяются.
- После переключения destination проверяется повторно. Для жителя: `/imtun/requests?requestId=<uuid>`.
- Недоступное уведомление не раскрывает содержимое заявки; отображается отказ доступа.

### Аренда → доступ

- Централизованная серверная политика учитывает даты аренды и отмену при каждой проверке контекста.
- Даты доступа считаются по календарю Asia/Yerevan.
- Пока у восстановленного арендатора нет записанных договоров для его помещения, прежний доступ сохраняется. После первого договора доступ определяется действующим неотменённым периодом.
- Будущий, истёкший или отменённый договор не разрешает новые защищённые действия.
- Управляющий может продлить период либо отменить договор с причиной и optimistic version.
- Пересечения действующих периодов запрещены; договоры, заявки и история не удаляются.
- Отдельная политика доступа бывшего арендатора к historical receipts/documents НЕ активирована: прежний договор сам по себе не даёт такого права.

## Проверки и сохранность

- Изолированные миграции 001–018, isolated seed только в случайной схеме `vernatun_test`.
- 91 проверка общей core-регрессии прошла. Отдельный финальный прогон Phase 3: 2 проверки календаря + 5 интеграционных групп прошли.
- Проверены конкурентная генерация, сохранение чек-листа, фото/отчёт/возврат/проверка управляющего, следующий цикл и replay старого цикла.
- Проверены foreign-tenant отказы с теми же полномочиями, срок/отмена/продление аренды, версии делегирования, свежая авторизация, token rotation, notification destination и перенос визита.
- OpenAPI/codegen, workspace typecheck и Vite production build прошли.
- Миграции 017–018 применены к development только после изолированной проверки.
- До/после применения совпали counts и digests прежних полей 14 таблиц; seed основной базы и удаление private bytes не выполнялись.
- Web/API перезапущены через существующие managed workflows; свежая сборка и authenticated GET-маршруты работают.
- Signed-in браузерная проверка новых интерфейсов выполняется; до её результата UI acceptance не объявляется завершённым.

## EXTERNAL BLOCKER / границы этапа

- Реальный email и тестовые письма не отправлялись. Домен не готов; внешний цикл приглашение → доставка → принятие настоящим адресатом пока не подтверждён.
- Телефон — контактная информация. SMS и phone-only authentication не реализуются в текущем scope; email остаётся обязательным для приглашения.
- Production migration, publish и проверка live webhook не выполнялись.
- Native/Expo, Boon и новые платёжные провайдеры не добавлялись.
- Phase 4–8 не объявляются завершёнными этим отчётом.
