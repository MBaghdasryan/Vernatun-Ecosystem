# Phase 7 — отчёт о реализации

Дата: 7 октября 2026. Vernatun Web и существующий API; новые Expo/native приложения не создавались.

## Итог

Основная реализация Phase 7 выполнена. Группирование зданий в самостоятельные объекты портфеля реализовано, включая интерфейс и ограничения доступа. Production readiness пока не объявляется: внешние подключения и заключительная приёмка относятся к отдельным пунктам ниже.

## COMPLETE — реализовано

### Уведомления
- Каталог 21 обязательного события, отдельное событие безопасности аккаунта и совместимость с прежними событиями заявок.
- Реальные in-app уведомления для заявок/визитов/работ, финансов, объявлений/собраний, поддержки и сроков.
- Глобальные пользовательские настройки in-app/email и настройки восьми категорий; применяются к будущим событиям без удаления истории.
- Версионирование настроек: конкурентное сохранение возвращает конфликт, а не перезаписывает чужие изменения.
- Явная обязательная политика только для безопасности аккаунта; обычные SLA/финансовые события не обходят отказ от уведомлений.
- Дедупликация новых событий, чтение только своих уведомлений и повторная проверка прав при переходе.
- Подтверждение переключения контекста сохранено. Ссылка не предоставляет дополнительных прав.
- Ручная идемпотентная проверка сроков пропусков, аренды, голосований и незавершённых задач внедрения, включая просроченные задачи.
- Email intentions остаются `pending_domain`; отправка не вызывается. SMS/push обозначены как будущие каналы.
- Подписи событий и новые элементы интерфейса доступны на hy/ru/en.

### Брендинг организации
- Название, основной/акцентный цвета, контакты поддержки, сайт, privacy и terms.
- Изменения доступны только пользователю с текущим `organization.settings`, с проверкой версии.
- HAYAT/ImTun используют выбранные цвета и приватный логотип; при отсутствии конфигурации/недоступности файла сохраняют исходные продуктовые логотипы.
- Конфигурация не меняет роли, подписки или доступ к данным.
- PNG/JPEG/WebP до 2 МБ; изображение проверяется и преобразуется в безопасный JPEG. SVG/HTML и произвольные URL логотипов запрещены.
- Логотип читается только при действующем доступе к организации, с `private, no-store`; не включается в PWA cache.
- Снятие логотипа удаляет ссылку, но не байты. Действующие ссылки включены в backup/live-reference inventory.

### Приватное хранилище
- Общий `PrivateStorageProvider`: App Storage, LocalPrivateStorage, S3CompatibleStorage.
- Восстановленное App Storage остаётся действующим вариантом по умолчанию.
- Local/S3 выбираются только явно; нет автоматического переноса, удаления или запасного переключения файлов.
- Существующие бизнес-проверки, sanitization, блокировки и неизменяемая запись файлов сохранены.
- Режим/готовность доступны в авторизованном интерфейсе без bucket names, путей или credentials.
- Существующие App Storage backup/inventory/cleanup tools отказываются работать в другом режиме. Local reviewed-generation deletion пока отключён; S3 требует versioning для такой операции.

### Ограниченный PWA
- Manifest, исходные брендовые иконки 192/512, поддержка браузерного install prompt и честная инструкция при его отсутствии.
- Offline fallback и allowlist только статических ресурсов; навигационные приватные ответы не кешируются.
- API/auth/финансы/документы/приватные фотографии, внешние адреса и URL с query-параметрами не добавляются в cache.
- Удаляется только старый cache оболочки, не IndexedDB с пользовательскими черновиками.
- Существующие пользовательские/контекстные черновики HAYAT и ручная синхронизация сохранены; фоновой отправки нет.
- Полный offline bootstrap не обещается для Vite development preview: production hashed assets и реальные устройства требуют отдельной приёмки.

### Группирование портфеля — функциональный объём закрыт
- Самостоятельный объект: название, тип, адрес/описание, версия.
- Создание, редактирование, просмотр, привязка/отвязка зданий через интерфейс.
- Одно здание относится максимум к одному объекту своей организации; межорганизационные связи запрещены.
- Для переноса требуется явная отвязка от предыдущего объекта.
- Удалять можно только пустой объект; здания, помещения и финансовая/операционная история не удаляются.
- Независимый фильтр объекта и здания в аналитике/scorecard. Exact minor-unit arithmetic сохранён.
- Прежний `propertyId` остаётся совместимым alias здания; новая группировка использует `portfolioObjectId`.
- Объекты не создавались автоматически в основной базе и существующие здания не перегруппировывались.

4. Production scheduler для due reminders не установлен; доступна ручная безопасная команда.
5. Установка PWA/offline на реальных iPhone/Android и production static build ещё требуют проверки. Native packaging, push/SMS и очередь офлайн-фотографий не заявляются готовыми.
6. Phase 8: заключительная межролевая, responsive/a11y/security/performance приёмка и production checklist не выполнялись в рамках этого этапа.
7. Browser gaps: edit/assignment пустого в основной базе портфеля и technician offline/local-draft journey требуют изолированного браузерного сценария; новый main seed для этого не выполнялся.

Production migrations, публикация, seed/reset основной базы, отправка писем, перенос или удаление приватных файлов не выполнялись.
