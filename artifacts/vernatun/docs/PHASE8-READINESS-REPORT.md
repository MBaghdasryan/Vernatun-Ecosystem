Дата: 2026-10-07. **Общий статус Phase 8: PARTIAL. Production-ready не заявляется.**

Продолжена существующая платформа Vernatun с Console, Vernatun OS, HAYAT и ImTun. Новые приложения, Expo, платёжные провайдеры и замена архитектуры не создавались.

## Выполнено в этом этапе

### 1. Реальная landing-заявка — COMPLETE для сохранения

- `POST /api/leads` сохраняет заявку в development PostgreSQL, вместо демонстрационного результата.
- Имя, email/телефон, организация, продукт, аудитория, сообщение, согласие, язык и время создания; ограничения длины, обязательное согласие, honeypot, отдельный лимит запросов.
- Сохранены CSRF/origin-проверки. Landing сначала получает сессию/CSRF, затем выполняет один POST. Автоматического повтора отправки нет.
- Подтверждение означает **сохранено**, а не «письмо доставлено». При успехе поля и согласие очищаются; при ошибке заполнение сохраняется.
- В Settings платформенного администратора доступен LeadsConsole: отдельное право `leads.read`, серверные поиск/сортировка/языковой фильтр/страницы, без перевода пользовательского содержимого.
- Браузер на отдельной настоящей тестовой базе подтвердил anonymous session 200 → lead 201 → очистку формы → отображение и серверный поиск записи в Console.
- Письма при создании заявки не отправляются. Уведомления менеджеру и эксплуатационные правила обработки/хранения заявок не являются результатом этого этапа.

### 2. Управляемая обязательная MFA — backend COMPLETE, UI acceptance PARTIAL

- Политика для глобального `platform_admin` и полного организационного `org_admin`.
- По умолчанию обязательность **не включена**: восстановленные пользователи внезапно не блокируются.
- Включение требует собственной настроенной MFA, проверки не старше 15 минут, причины и даты активации минимум через 24 часа.
- Version/CAS защищает от перезаписи параллельной настройки; изменение аудитируется.
- После срока сервер проверяет MFA на свежем бизнес-контексте. Старой сессии без подтверждения недостаточно.
- Настройка, статус MFA и повторная аутентификация доступны, чтобы пользователь мог выполнить требование.
- Нельзя отключить MFA, пока хотя бы одна применимая политика требует её; recovery-коды одноразовые, TOTP защищён от повторного использования.
- Settings показывает политику, срок UTC, enrollment/proof, явное обновление статуса и повторную проверку пароля/MFA.
- Изолированные API-тесты проверили grace, запрет без подтверждения, stale-version, принудительный gate старой сессии и recovery.
- **Не подтверждено браузером:** полный UI enrollment → policy save → enforcement. Политики основной базы автоматически не активировались.

### 3. Масштабируемые списки — PARTIAL

- Новый `GET /api/paged/{resource}` для организаций, зданий, помещений, людей, приглашений и аудита.
- Свежая серверная авторизация; organization/building/unit scope; SQL-поиск, сортировка по allow-list, стабильный id tie-breaker, page/pageSize, максимум 100 записей страницы.
- Общий DataTable канонических OS/Console/HAYAT record-маршрутов подключён к серверному контракту. Сводки и небольшие фиксированные справочники остаются локальными.
- Legacy-массивы organizations/properties/units/people ограничены 1000 строками. Старые уже пагинированные контракты приглашений и аудита не заменены.
- API-тесты подтвердили ограничения, неверную сортировку, отдельные права и unit scope.
- **Осталось:** единая серверная пагинация остальных растущих operational/financial/document списков, поиск больших lookup-справочников вместо legacy ceiling, браузерная приёмка новых record-таблиц.

### 4. Роли, локализация, адаптивность и доступность — PARTIAL

- API dashboards проверены для 14 уникальных ролей; метрики реальные и scoped.
- Исправлена дублирующаяся карточка `openSupport`. Модули метрик теперь используют effective context modules, а не только исходные entitlement-флаги.
- Новые экраны и MFA-ошибки имеют hy/ru/en. Пользовательский текст не переводится; исходные логотипы, тексты и изображения landing не заменялись.
- Проверены public landing widths 360/390/768/1024/1440, наличие логотипов, desktop/mobile navigation, skip-link и ошибки обязательных полей/согласия.
- Отдельный реальный screenshot `/login` на 390 px показывает работающую форму входа.
- **Осталось:** authenticated matrix всех ролей/экранов на всех пяти ширинах, полный keyboard/dialog/focus/contrast аудит.
- **Timezone scan не закрыт:** найдены UTC-derived calendar defaults в Maintenance, Ownership и EmailConsole; общая настройка org/user timezone и полный аудит business dates ещё не приняты.

### 5. API и security readiness — PARTIAL

- В canonical OpenAPI добавлены leads, MFA policy, scoped record paging и private branding-logo response. Клиенты/Zod regenerated, shared typecheck проходит.
- Статический inventory: **228** найденных mounted операций, **110** представлены в canonical OpenAPI, **118** ещё не сопоставлены.
- Inventory не доказывает корректность всех схем: dynamic routes и legacy served OpenAPI требуют отдельной сверки.
- Dependency scan до исправлений: 1 critical / 6 high / 3 moderate; после: **0 critical / 1 high / 0 moderate**.
- Остался `braces@3.0.3`, upstream stack-exhaustion advisory без доступного исправления. В dependency graph API-server пакет не найден; workspace build/tooling risk остаётся.
- SAST и privacy scan: замечаний не возвращено. Это не сертификация безопасности и не отменяет оставшийся advisory.
- Production не публиковался, production DB не мигрировалась. Внешний домен/email delivery, production storage/backup, cron и эксплуатационные проверки сохраняют прежние ограничения.
