# Почта Vernatun — состояние и настройка

## Текущее состояние

Выбран `MAIL_PROVIDER=resend`, пользователь сохранил `EMAIL_FROM` в shared environment. Интеграция подключена, но read-only запрос списка доменов всё ещё возвращает 400 `validation_error`: «API key is invalid». Ключ нужно исправить в существующей интеграции; реальные письма не отправлялись. Адрес отправителя задан, но подтверждение его домена проверить не удалось из-за отказа авторизации.

Общий `EmailProvider` имеет отдельные `ResendEmailProvider`, `SMTPEmailProvider` и `DevelopmentOutboxProvider`. Приглашения, семейное делегирование и сброс пароля используют неизменённый общий facade. Новый provider подключается в registry, без изменения бизнес-логики.

Production запрещает outbox и возвращает configuration error при неполной настройке. Выбранный, но неисправный provider не заменяется молча локальной доставкой. Автоматические тесты принудительно выбирают приватный outbox, даже при унаследованных реальных настройках.

## Resend

- `MAIL_PROVIDER=resend`, `EMAIL_FROM` — подтверждённый адрес отправителя.
- Credentials хранятся в подключённой интеграции. Сервер использует `@replit/connectors-sdk`; отдельный `RESEND_API_KEY` не нужен.
- SDK заново получает identity для запроса, не хранит долгоживущий клиент/ключ.
- Запрос ограничен 20 секундами; принятие подтверждается только успешным HTTP-ответом с валидным message ID.
- Idempotency key учитывает business key и hash фактического содержимого: повторная транспортная попытка не создаёт новую отправку, а обновлённый invitation/reset token получает другой ключ.
- Ошибки/timeout/невалидный receipt не считаются успехом; provider error body и URL/token не возвращаются клиенту.

## Переключение

`MAIL_PROVIDER=smtp` выбирает SMTP, `MAIL_PROVIDER=outbox` разрешён только в development. `EMAIL_FROM` — общий адрес; `SMTP_FROM` остаётся совместимым fallback. В test mode always outbox. Смена настройки не требует изменения invitation/reset/delegation endpoints.

## Настройки серверного процесса

| Ключ | Назначение |
|---|---|
| `MAIL_PROVIDER=smtp` | Выбор SMTP |
| `SMTP_HOST` | Сервер выбранного почтового провайдера |
| `SMTP_PORT` | Обычно 587 (STARTTLS) или 465 (TLS); уточнить у провайдера |
| `SMTP_FROM` | Подтверждённый адрес отправителя, без display-name |
| `EMAIL_FROM` | Общий подтверждённый адрес; имеет приоритет над `SMTP_FROM` |
| `SMTP_USER` | SMTP login — вводить через защищённый механизм секретов |
| `SMTP_PASS` | SMTP password — вводить через защищённый механизм секретов |

`SMTP_PASSWORD` поддерживается только как совместимый alias, если `SMTP_PASS` отсутствует. Предпочтителен ключ `SMTP_PASS` из спецификации.

Не добавлять credentials в исходники, документацию, чат или клиентские `VITE_*` переменные. Не использовать данные демонстрационных пользователей как почтовые credentials.

Ссылки формируются из серверного `APP_ORIGIN`. Перед запуском production он должен соответствовать подтверждённому публичному домену приложения; development domain не считается автоматически production domain.

## Что считать подтверждением

- `local_only`: письмо доступно только в приватном development/test outbox.
- `smtp_accepted`: SMTP-сервер принял адресата и сообщение без rejected recipients. Это **не** гарантия попадания в mailbox.
- `resend_accepted`: API Resend принял запрос и вернул message ID. Это **не** гарантия попадания в mailbox.
- Ошибка настройки/отправки: явная ошибка, без ложного сообщения «письмо отправлено».

Ключ не присылать в чат и не переносить в код. Затем проверить получение на разрешённом реальном тестовом адресе и invitation acceptance/single-use reset. Сейчас live delivery test не выполнен. Асинхронные mailbox-delivered/bounced events пока не отслеживаются; «sent» в invitation list означает только принятие сервисом.
