Дата: 2026-10-07.

Общее:

- Исходные логотипы и разделение Vernatun / HAYAT / ImTun сохранены.
- Новые подписи переведены на RU/HY/EN.
- Ошибка, загрузка и пустой результат различаются; предусмотрена повторная загрузка.
- Ограниченные выдачи обозначаются как preview, а не как общее число записей.
- Ошибка календарного источника не превращается в сообщение «ничего нет».
- Скрытие предупреждения об инциденте не закрывает сам инцидент.
- Финансовый месяц применяется только к денежным KPI; операционные показывают текущее состояние.
- Изменены не только ссылки: HAYAT читает фильтр статуса из URL, FinanceWorkspace
  читает и сохраняет `tab=bank|credits|batches`.

## Продолжение: подрядчик ↔ застройщик

Реализованы в карточке дефекта HAYAT и в OS:

- Отправка и чтение уточнений с автором и временем.
- Сохранение после повторного входа/обновления; обновление по кнопке,
  возврату фокуса и каждые 15 секунд на видимой вкладке.
- Предыдущие страницы переписки и возврат к последним сообщениям.
- Неизменяемые отправленные сообщения; они не переводят дефект в другой статус.
- Идемпотентная отправка: при повторе сохраняется один экземпляр.
- Отдельный блок фотографий и истории отчётов/возвратов/приёмки.
- Исправлены ссылки старой карточки HAYAT: фото дефекта скачиваются через
  защищённый `/api/defect-photos/:id`, а не через `/api/photos/:id` для заявок.

Сообщения используют существующий неизменяемый журнал дефекта; миграции не
потребовались. Аудит фиксирует ID сообщения, не копирует текст переписки.
Проверки доступа выполняются до повтора сохранённого результата операции.
После переназначения подрядчик теряет доступ и к обсуждению, и к фотографиям.
Права на общие документы или чужие объекты не добавлены.

## Продолжение: расписание визитов

Существующий блок расписания HAYAT для диспетчера, управляющего и техника
расширен без изменения прав и схемы базы:

- Выбор включительного периода до 62 дней; по умолчанию сегодня в Asia/Yerevan.
- Фильтры по зданию и назначенному исполнителю, включая визиты без исполнителя.
- Имена исполнителей, переведённые статусы и переход в существующую карточку заявки.
- Отметки пересечения временных интервалов одного исполнителя среди доступных
  пользователю визитов. Это не признак фактической занятости вне доступной области.
- Обновление каждые 30 секунд на видимой вкладке, при возврате фокуса/сети и вручную.
- Явные состояния загрузки, ошибки, пустого результата и неверного периода.
- При более 1000 совпадениях API требует сократить период, а не отдаёт незаметно

## Продолжение: смены, отсутствия и доступность сотрудников

**Реализовано и проверено в рамках разрешённой области:**

- На `/hayat/calendar` доступны выбор разрешённого помещения и точного интервала
  по времени Еревана, список исполнителей и сохранённых смен/отсутствий.
- Создание, изменение и подтверждаемая отмена. Отмена сохраняет запись;
  изменения пишутся в аудит. Неоднозначный повтор запроса использует тот же ключ,
  устаревшая версия отклоняется вместо перезаписи чужого изменения.
- Область записи — помещение или здание. Пользователь, ограниченный помещением,
  не может менять план всего здания. Стандартный техник видит свои данные без
  управления; сервер проверяет фактические права, а не только наличие кнопок.
- Статус для выбранного интервала: неизвестно / доступен в разрешённой области /
  занят визитом / отсутствует. Смена должна покрывать весь интервал, включая
  объединение смежных смен; разрыв не считается рабочим временем.
- Учитываются активные визиты, периоды отсутствия и действие назначения роли
  сотрудника на всём интервале. Отсутствие смены не означает свободу.
- Обновление по таймеру, при возврате в окно и восстановлении соединения;
  фоновых записей нет. Открытая форма не сбрасывается обновлением данных,
  переключение её области/периода блокируется до закрытия.
- Начальный период проверки — следующий день; новая форма наследует выбранный
  интервал. Отказ при периоде вне действующего назначения объясняется отдельно.

**Проверки:**

- Миграция добавляет только новую таблицу и индексы. Сравнение контрольных сумм
  и количества строк 13 существующих таблиц прошло как в изолированной базе,
  так и при применении к development-базе. Production не изменялась.
- Шесть групп серверных тестов: интервалы, полный цикл, повтор запросов, аудит,
  конкурентные изменения, чужая организация/роль, ограничения помещения,
  действие роли, занятость визитом и отмена — PASS.
- Проверка типов API и web и production build — PASS.
- Браузер, изолированные данные: создание → перезагрузка → изменение →
  перезагрузка → пересекающееся отсутствие → подтверждённая отмена — PASS.
- Техник: только собственное помещение из работ, режим просмотра — PASS.
- Подрядчик: пункта календаря нет; прямая ссылка не показывает данные и
  элементы календаря. При этом отображается общее пустое состояние, а не

- Сохранение дат календаря визитов в URL после перезагрузки — PASS.
- 390 и 1440 пикселей: горизонтального переполнения страницы нет, мобильные

**Границы:** это планирование в разрешённой области, не кадровый табель и не
оформление отпусков по всей компании. Статус не выполняет автоматическое
