# Ролевые главные экраны — прогресс после IAM

Дата: 2026-10-07.

**Общий статус: PARTIAL.** Этот документ не заменяет исходную матрицу
REFERENCE-SCREEN-GAP-REPORT и не объявляет все 14 ролей завершёнными.

## Порядок работ, подтверждённый пользователем

1. Экраны и приёмка ролей.
2. Platform Operations Center.
3. Payments & Utility Billing.

Следующие два направления пока не начаты. Существующий IAM сохранён.

## Реализовано в этой итерации

| Роль | Добавления к существующим рабочим экранам |
|---|---|
| Platform admin | Открытые обращения поддержки, незавершённые этапы внедрения, KPI и быстрые переходы в разрешённые разделы Console. Нет выдуманного графика SaaS-выручки. |
| Support | Свои обращения, открытые этапы внедрения, сроки, переходы к временному доступу и разрешённому импорту. |
| Org admin | Ожидающие приглашения и быстрые переходы к сотрудникам, ролям, объектам, модулям, аудиту и настройкам. |
| Accountant | Несопоставленные банковские строки, переход сразу во вкладку сверки, вкладки начислений и кредитов, фильтр месяца финансовых KPI. |
| Portfolio owner | Расходы на согласовании, истекающая аренда, переходы к аналитике, бюджетам, счетам и договорам. |
| Developer | Предстоящие осмотры и истекающие гарантии из реальных актов передачи. |
| Manager | Работы на приёмке, активные инциденты, объявления, собрания и переходы к действующим модулям HAYAT. |
| Dispatcher | Новые заявки, активные инциденты, переходы к очереди с работающими фильтрами статуса. |
| Technician | Ролевые KPI и переходы к назначенным работам, работам в процессе и доступному оборудованию. |
| Contractor | Переходы к назначенным дефектам, работам в процессе и результатам на проверке. |
| Security | Разрешённые инциденты и переходы к событиям; отсутствие физического контроллера не выдаётся за подключение. |
| Unit owner | Ожидающие подтверждения результаты собственных заявок с переходом в карточку. |
| Renter | Ожидающие подтверждения результаты собственных заявок и актуальное окончание аренды. |
| Family | Контакты управляющей организации только из её настроек; финансовые права не добавлены. |

Общее:

- Исходные логотипы и разделение Vernatun / HAYAT / ImTun сохранены.
- Новые подписи переведены на RU/HY/EN.
- Ошибка, загрузка и пустой результат различаются; предусмотрена повторная загрузка.
- Ограниченные выдачи обозначаются как preview, а не как общее число записей.
- Ошибка календарного источника не превращается в сообщение «ничего нет».
- Скрытие предупреждения об инциденте не закрывает сам инцидент.
- Финансовый месяц применяется только к денежным KPI; операционные показывают текущее состояние.
- Изменены не только ссылки: HAYAT читает фильтр статуса из URL, FinanceWorkspace
  читает и сохраняет `tab=bank|credits|batches`.

## Серверные изменения

- Счётчик сотрудников учитывает границу помещения и исключает заблокированные аккаунты.
- Счётчик приглашений учитывает границы здания и помещения.
- Platform admin видит количество всех незавершённых этапов внедрения,
  support — только назначенных ему.
- Финансовые KPI принимают необязательный `period=YYYY-MM` и продолжают проверять
  организацию, здание, помещение, фактического плательщика, валюту, права и модуль.
- Контракт `/role-insights` добавлен в OpenAPI, клиенты пересозданы.
- Новых миграций нет. Основные бизнес-данные не изменялись.

из каталога архивного сервера.

### Браузерная проверка главных экранов

- Проверены UI-вход и стартовый маршрут всех 14 ролей.
- Проверены переходы с главной страницы, фильтры HAYAT, финансовый месяц,
  вкладки начислений/сверки/кредитов и сохранение контекста после reload.
- Дополнительная организация видит свой список объектов; platform admin
  не получает tenant-доступ при прямом переходе в OS.
- Family не получает финансы/голосование/администрирование; renter — ownership;
  dispatcher — приёмку работ.
- На главной OS проверены 360/390/768/1024/1440 px.
- Найдены и исправлены сырые ключи заголовков таблицы зданий и горизонтальное
  переполнение Console. Повторная целевая проверка прошла:
  Console 1440 px — document/body 1425/1425 px;
  Console 390 px — 375/375 px; мобильное меню 270/270 px.
- Заголовки зданий проверены на армянском и русском.
- Широкая таблица зданий на 390 px прокручивается внутри контейнера;
  документ целиком не переполняется.

**Ограничения:** эта проверка не выполняла создание/изменение бизнес-записей.
Ни один из семи сквозных сценариев в этой итерации не завершён.
Полная responsive-матрица каждого продукта и все действия каждой роли
не проверены. Результат — приёмка изменённых главных экранов и исправлений,
а не COMPLETE всех требований референсов.

## Остаётся реализовать, а не объявлять внешним блокером

- Планы помещений, расположение дефектов на плане и readiness по этажам.
- Диагностика, расписание встреч и база знаний поддержки.
- Уточняющая переписка и отдельная безопасная выдача материалов подрядчика.
- Полная композиция диспетчерского расписания/доступности исполнителей.
- Единый поиск с авторизацией и выпадающие уведомления в шапке.
- Остальные действия/состояния из исходной матрицы, не перечисленные выше как реализованные.
- Полная приёмка действий всех ролей и семи сквозных сценариев.

Права portfolio owner на общие service/documents нельзя расширять по картинке.
Contractor scorecard уже имеет серверную политику: проверять её фактические
разрешения и модуль, а не считать всю функцию отсутствующей.

## Внешние подключения и последующие этапы

Реальные SaaS-платежи, банковский провайдер, SMS, телефония, платёжный шлюз,
физическое открытие двери и карта без геоданных не имитируются.
Сообщение «не подключено» не считается реализацией отсутствующей внутренней функции.
