# HAYAT — отчёт о восстановлении и текущем состоянии

Дата проверки: 6 октября 2026 года.

## Что именно восстановлено

По выбранному варианту HAYAT восстановлен **как веб-модуль внутри Vernatun**, а не как отдельное приложение Expo. В ZIP находятся только четыре файла React/Vite: `HayatApp.tsx`, `hayat.css`, `i18n.ts` и `config.ts`. Нативных исходников, проектов iOS/Android, APK/IPA и конфигурации Expo в архиве нет.

Основа отчёта — приложенный `HAYAT-IMPLEMENTATION_1791285553155.md`. Его заявления о тестах от 30 сентября — исторические сведения, не результаты текущего восстановления. Исходный приложенный MD и ZIP оставлены без изменений.

### Восстановлено из ZIP

- Интерфейс HAYAT, его исходные стили, тексты HY/RU/EN и логотип.
- Пять рабочих пространств: управляющий, диспетчер, техник, подрядчик и охрана.
- Настольная навигация, мобильная навигация, карточки, таблица и канбан.
- Формы и экраны, использующие общие запросы, дефекты, пропуска, инциденты, документы, объявления, собрания и обслуживание Vernatun.
- Настройки бренда и описательная информация для будущих сборок. Такая информация сама по себе не создаёт нативное приложение.

### Восстановлены отсутствовавшие связующие элементы

- Подключение HAYAT к общему авторизованному порталу Vernatun.
- `GET /api/hayat/queue`: **исходник серверной очереди в ZIP отсутствовал**, поэтому она воссоздана по контракту UI и описанию в MD. Используются существующие таблицы, действующий контекст, разрешения и ограничения организации/здания/помещения. Техник видит только назначенные ему работы, подрядчик — назначенные ему дефекты.
- Серверные поиск, фильтрация, статистика и страницы по 24 записи. Чтение выполняется в одной согласованной read-only транзакции.
- Режим `detailOnly` общего `Workflow`: подробности заявки без второй очереди и повторной загрузки полного списка.
- Локальные типы конфигурации вместо отсутствующего импорта `src/imtun/config.ts`. Сам отсутствовавший модуль ImTun этим не воссоздавался.
- Новые тесты очереди и описание её API-контракта.

**Не менялись:** роли, набор разрешений, схема основной БД, существующие бизнес-данные, аккаунты, изображения и логотипы. Миграции и тестовые записи запускались только в изолированной тестовой базе/схеме, которая удаляется после тестов.

## Сделано и что ещё отсутствует

«Восстановлено» означает, что код доступен и подключён к существующему серверу. Это не означает, что каждая операция записи повторно проверена на пользовательской базе. Изменять её данные ради такой проверки не требовалось.

| Область | Текущий статус | Ограничение / что ещё не сделано |
|---|---|---|
| Пять ролевых рабочих пространств | Восстановлено | Доступ определяется активным серверным контекстом, не выбранным адресом страницы |
| Обзор управляющего | Частично | Реальные показатели очереди есть; отдельной аналитики загрузки команды нет |
| Здания, помещения и команда | Подключено к общим экранам | Отдельная новая модель этих сущностей не создавалась |
| Очередь диспетчера | Восстановлено | Поиск, статусы, здания, таблица/канбан, страницы по 24 записи |
| Назначение работ, чек-листы, сообщения | Подключено к общему Workflow | Нет отдельного сценария телефонной заявки, приоритетов и переноса сроков |
| Рабочая карточка техника | Восстановлено | Старт, чек-лист, фото, отчёт и история используют существующий Workflow; нет паузы, материалов, календаря визитов и QR оборудования |
| Рабочая карточка подрядчика | Восстановлено | Назначенные дефекты, старт, фото и отчёт; нет отдельной связи дефект → наряд |
| Проверка результата | Подключено к существующему процессу | Подрядчик не получает право принимать собственную работу; подтверждение жителя остаётся в общем процессе |
| Пропуска и журнал входа/выхода | Восстановлено | Проверка токена вручную; камера для сканирования QR не подключена |
| Контроллер доступа | Не подключён | Нет интеграции с физическим оборудованием |
| Инциденты охраны | Частично | Создание есть; нет полноценного цикла обработки, серьёзности, вложений и отдельного обзора управляющего |
| Оборудование и обслуживание | Частично | Используются общие экраны; права техника не расширялись, автоматического создания нарядов нет |
| SLA, приоритеты и календарь | Не реализовано | Их нельзя считать восстановленными только по наличию статусов и времени |
| Локальные черновики | Частично | Ручное сохранение текста и чек-листа; нет полноценного открытия работы после офлайн-перезагрузки, очереди фото и фоновой синхронизации |
| Внутренние уведомления | Подключено | Нативные push-уведомления не подключены |
| Обновления в реальном времени | Не реализовано | Нет WebSocket/SSE; используется обновление запросами |
| HY/RU/EN и даты | Восстановлено | Переводы взяты из ZIP; рабочие даты отображаются с учётом Asia/Yerevan |
| White-label | Частично | Цвет бренда и метаданные есть; отдельные приложения организаций, загрузка логотипов через API и магазинные сборки отсутствуют |
| iOS/Android | Только адаптивный Web | Нативная сборка, Expo, APK/IPA и публикация в магазинах не восстановлены, поскольку их исходники не предоставлены |
| Финансы | Ссылка на Vernatun OS | Отдельный финансовый движок HAYAT не создавался |
| Масштабирование | Частично | Новая очередь имеет серверную пагинацию; остальные общие экраны сохраняют прежние ограничения |
| Отдельный экран входа с брендом HAYAT | Не подключён | Вход остаётся общим экраном Vernatun; наличие CSS в ZIP не означает отдельного восстановленного auth-компонента |

## Чего не было в предоставленных исходниках

В историческом MD упомянуты, но не включены в ZIP:

- `server/hayat.ts` — восстановлен по контракту, не скопирован из исходного проекта.
- `server/tests/hayat.test.ts` — вместо отсутствующих исторических тестов добавлены новые.
- `scripts/hayat-dev.cjs`, `scripts/hayat-qa.cjs` — не предоставлены и не выдаются за восстановленные.
- Исторические скриншоты `docs/hayat-preview/` — не предоставлены.
- Нативные проекты и настройки магазинных сборок — не предоставлены.

В Replit модуль обслуживают уже существующие процессы API Server и Vernatun Web. Отдельный сервер HAYAT не нужен.

## Проверки текущего восстановления

| Проверка | Результат |
|---|---|
| TypeScript, Vernatun Web | Пройдено |
| TypeScript, API Server | Пройдено |
| Производственная сборка Vite | Пройдено |
| Новые изолированные API-тесты HAYAT | 4 из 4 пройдены |
| Браузерная проверка защищённых экранов | Пройдена для управляющего на desktop и техника на мобильном экране 390×844; полный браузерный прогон пяти ролей не выполнялся |

В браузере проверены вход, HAYAT-навигация, очередь, поиск по названию, фильтр статуса, таблица/канбан, открытие и возврат из карточки работы. Карточка не дублирует очередь и показатели. На мобильных списке и подробностях техника горизонтального переполнения не обнаружено. Рабочие действия записи не выполнялись.

Обнаруженная при браузерной проверке ошибка поиска по короткому отображаемому номеру `WO-…` исправлена на сервере. Добавлены регрессионные API-проверки коротких номеров работы и заявки. Повторный браузерный прогон после этого небольшого серверного исправления не выполнялся.

Четыре текущих API-теста проверяют:

1. Отказ без входа и для неподходящей роли; валидацию параметров.
2. Поиск, включая короткие отображаемые номера, статистику, статусы, страницы и отсутствие данных другой организации.
3. Персональные назначения техника/подрядчика, отключённый контекст и отключённый модуль.
4. Истёкшие, отозванные и ещё не действующие пропуска; отсутствие секретных токенов в ответе очереди.

Команда целевого серверного теста из каталога `artifacts/api-server/archive/vernatun`:

```sh
node --import tsx server/tests/run.ts --hayat-only
```

Историческое заявление «34 API-теста и Playwright для пяти ролей» в этом отчёте **не считается текущим результатом**.
