# Передача релиза Vernatun в Coolify

## Состав

- В разделе «Пользователи» добавлены фильтр по дате создания и экспорт CSV.
- API поддерживает параметры `createdFrom` и `createdTo` для списка пользователей.
- Экспорт выполняется через `GET /api/iam/users/export.csv`, ограничен platform admin, учитывает поиск и диапазон дат, защищает CSV от формул и записывает событие аудита.
- Для приглашения внутренних сотрудников Vernatun требуется SQL-миграция `059_platform_staff_invitations.sql`.
- Сборка API копирует полный каталог SQL-миграций в `dist/migrations` и останавливается, если состав исходных и упакованных миграций не совпадает. В пакет входит `dist/migrations/059_platform_staff_invitations.sql`.

## Статус баз данных

- Миграция 059 проверена изолированными тестами.
- Development-база Replit уже содержит миграцию 059; ожидающих миграций и расхождений не обнаружено.
- База Coolify/Production не изменялась. Наличие файла в пакете не означает, что миграция уже применена в Production.
- Для будущего релизного манифеста укажите `databaseMigrationRequired: true`.

## Порядок выкладки в Coolify

1. Соберите API из этого исходного кода и проверьте наличие `dist/migrations/059_platform_staff_invitations.sql` в образе/пакете.
2. Подтвердите резервную копию Production и возможность восстановления.
3. В API-контейнере Coolify выполните штатный read-only preflight: `pnpm --filter @workspace/api-server run db:migrate:coolify:plan`.
4. Продолжайте только при ожидаемой базе `vernatun`, отсутствии drift и согласованном списке pending-миграций. Мигратор применяет все pending-миграции по порядку, поэтому при неожиданном списке остановитесь.
5. Применяйте миграции только после проверки backup и плана, штатной командой Coolify. Не запускайте development-команду `db:migrate` против Production.
6. После миграции разверните API и проверьте health-check, приглашение внутреннего сотрудника, список/экспорт пользователей и запись аудита.

Секреты и значения переменных окружения в этот файл не включать.
