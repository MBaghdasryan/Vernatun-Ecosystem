# Безопасное восстановление глобальной учётной записи Vernatun

Команда восстанавливает пароль **только существующего** активного пользователя с действующим глобальным назначением `platform_admin` или `support`. Она не создаёт пользователей, не меняет назначения ролей и не отключает MFA.

## Подготовка

1. Убедитесь, что в Coolify развернута версия API с этой recovery-командой.
2. Запускайте её только в shell API-контейнера, подключённого к production базе `vernatun`.
3. На каждый аккаунт выполняйте отдельный вызов. Укажите известный адрес и соответствующую ему роль; адреса и пароли не добавляйте в репозиторий.

## Запуск

Для `platform_admin`:

```bash
VERNATUN_ACCOUNT_RECOVERY_CONFIRM=RESET_GLOBAL_ACCOUNT NODE_ENV=production \
corepack pnpm --filter @workspace/api-server run db:recover:global-account -- \
  --email=platform.admin@vernatun.test \
  --role=platform_admin \
  --confirm-production-account-recovery
```

Для `support` выполните отдельную команду с `--email=support@vernatun.test` и `--role=support`.
Указанные адреса должны уже существовать в production и иметь соответствующее активное глобальное назначение. Скрипт не создаст отсутствующую учётную запись.

Операция остановится без изменений, если база не называется `vernatun`, пользователь отсутствует или заблокирован, либо у него нет ровно одного действующего глобального назначения указанной роли. Пароль создаётся случайно, сохраняется во временный JSON-файл `/tmp` с правами `0600` и никогда не печатается. Путь к файлу выводится после успешного commit.

## После сброса

- Заберите файл из того же контейнера по выведенному пути через защищённую консоль. Не копируйте его содержимое в логи, чат, тикет или GitHub.
- Войдите и сразу смените пароль в настройках аккаунта.
- MFA остаётся включённой. Если MFA-код или recovery-коды недоступны, эта команда не обходит MFA; используйте отдельный подтверждённый процесс восстановления MFA.
- Все существующие сессии пользователя отзываются; незавершённые ссылки сброса пароля становятся недействительными.
- После безопасного сохранения нового пароля удалите временный JSON-файл из контейнера.
