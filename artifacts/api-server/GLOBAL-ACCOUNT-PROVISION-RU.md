# Создание двух глобальных аккаунтов Vernatun

Эта команда создаёт новые учётные записи только для ролей `platform_admin` и `support`. Она не сбрасывает и не изменяет существующие аккаунты. Если хотя бы один указанный адрес уже занят, команда прекращает работу без изменений.

## Требования

- В Coolify уже развёрнута версия API, содержащая `db:provision:global-accounts`.
- Команда запускается в shell контейнера API, подключённого к production базе `vernatun`.
- Для этого запуска пользователь подтвердил создание обоих глобальных аккаунтов.
- `platform_admin` имеет полный доступ ко всей платформе. Используйте этот адрес только если почтовый ящик контролируется доверенным ответственным лицом; предпочтителен персональный именной адрес.

## Запуск

Подставьте подтверждённые адреса в терминале Coolify; не записывайте их в Git:

```bash
VERNATUN_GLOBAL_ACCOUNT_CONFIRM=CREATE_GLOBAL_ACCOUNTS \
NODE_ENV=production \
corepack pnpm --filter @workspace/api-server run db:provision:global-accounts -- \
  --platform-admin-email=<адрес-администратора> \
  --support-email=<адрес-поддержки> \
  --confirm-production-global-account-provision
```

Скрипт требует production-режим, имя базы `vernatun`, схему `public`, обе системные роли и необходимые таблицы. Создание выполняется в одной транзакции; пароли случайные, хешируются bcrypt и не выводятся в терминал. Email не отправляется. При успехе создаётся JSON с учётными данными в `/tmp` с правами `0600`; путь будет показан в результате.

При сбое CLI выводит только безопасную JSON-диагностику: этап, категорию, класс ошибки, SQLSTATE или filesystem-код, а также безопасные имена таблицы/колонки/ограничения, если PostgreSQL их предоставил. Сообщение драйвера, параметры SQL, адреса email, пароли и `DATABASE_URL` в этот вывод не включаются. Исправленный audit insert явно приводит роль к `text` для `jsonb_build_object`; не повторяйте provisioning до устранения указанного этапа ошибки.

## Первый вход, проверка и удаление временных паролей

Файл содержит одноразовые пароли и должен оставаться только в Coolify-контейнере с правами `0600`. Не копируйте его в GitHub, чат, тикет или логи. Для хранения новых паролей используйте доверенный менеджер паролей.

1. Откройте `https://vernatun.io/login` и войдите в `platform_admin`, используя пароль из файла.
2. В меню откройте **Настройки → Сменить пароль**. Задайте уникальный пароль, сохраните его в менеджере паролей, выйдите из аккаунта и проверьте повторный вход с новым паролем.
3. В той же странице **Настройки** откройте секцию **MFA**, нажмите **Настроить**, подтвердите текущий пароль, отсканируйте QR-код приложением-аутентификатором и введите текущий TOTP-код. Сохраните выданные recovery codes в менеджере паролей; закройте QR-код и не сохраняйте его в скриншотах.
4. Выйдите и войдите в `platform_admin` ещё раз, подтвердив вход новым паролем и TOTP-кодом. Убедитесь, что в Vernatun отображается роль `platform_admin`.
5. Повторите шаги 1–2 для `support`, подтвердите, что после повторного входа отображается роль `support`. Не используйте пароль администратора для аккаунта поддержки.
6. Только после успешного повторного входа в оба аккаунта и проверки MFA администратора удалите файл **в том же API-контейнере Coolify**, подставив точный путь из результата provisioning:

   ```bash
   rm -- <выведенный-путь>
   ```

Если вход, смена пароля или MFA не завершились успешно, не удаляйте файл до восстановления доступа. Не вставляйте содержимое файла или пароли в чат для диагностики.

Команда не обходит существующие правила MFA и не меняет базу вне указанных двух новых аккаунтов, их ролей и соответствующих записей аудита.
