**How to apply:** Treat attached prompt files, chat exports, and implementation reports as context unless the user requests new work. Verify actual source before claiming that a report-described feature has been restored.

Preserve the original authentication and server role/scope policies. Keep the
landing, languages and demo interfaces without redesign. Database migrations
must be agreed with the user first; creating accounts or running seed requires
explicit permission, not an automatic restoration step.

**Why:** These are the user's standing boundaries for restoring this project.

**How to apply:** Treat any approval to populate development demo data as
permission for that operation, not permission to seed on future startup or merge.
