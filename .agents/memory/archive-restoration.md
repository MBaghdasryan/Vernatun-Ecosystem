name: Archive restoration scope
description: How to interpret the archive and historical prompts in this recreated Vernatun project.
---

Restore the supplied source archive faithfully rather than rebuilding the site from historical prompts.

**Why:** The user explicitly asked to open the same archived site in this recreated project, not to redesign it or execute every past prompt.

**How to apply:** Treat attached prompt files, chat exports, and implementation reports as context unless the user requests new work. Verify actual source before claiming that a report-described feature has been restored.

Preserve the original authentication and server role/scope policies. Keep the
landing, languages and demo interfaces without redesign. Database migrations
must be agreed with the user first; creating accounts or running seed requires
explicit permission, not an automatic restoration step.

**Why:** These are the user's standing boundaries for restoring this project.

**How to apply:** Treat any approval to populate development demo data as
permission for that operation, not permission to seed on future startup or merge.

For overlap corrections on the landing page, change layout only; preserve
the supplied logos, images and text.

**Why:** The user repeated this constraint when requesting fixes to the header,
hero, footer and product cards.

**How to apply:** Adjust flow, spacing, sizing and responsive placement without
rewriting content, replacing assets or redesigning their visual identity.
