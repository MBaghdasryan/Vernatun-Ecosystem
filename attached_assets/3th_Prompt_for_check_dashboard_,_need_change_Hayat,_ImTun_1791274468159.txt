Проверь фактическую реализацию Vernatun Console
в текущем проекте. Пока ничего не изменяй.

В наших предыдущих заданиях этот контур сначала назывался
«Админ-панель Vernatun» с маршрутами /platform,
затем — Vernatun Console с маршрутами /console.

Не делай выводы по текстам промптов, README или названиям меню.
Проверь код страниц, API, авторизацию и схему базы данных.

Найди и проверь:

1. Дашборд администратора платформы.
2. Дашборд внедрения и поддержки.
3. Управление организациями и приглашение их администраторов.
4. Подписки, тарифные планы и доступность модулей.
5. Этапы внедрения и импорт данных с предварительной проверкой.
6. Обращения поддержки.
7. Запрос, одобрение, истечение и отзыв временного доступа поддержки.
8. Аудит административных действий.
9. Серверный запрет доступа в Console для клиентских пользователей.
10. Действующие маршруты /platform и /console.
11. Источник данных дашбордов: база, API или статические фикстуры.

Для каждого пункта укажи:
- реализовано полностью / частично / отсутствует;
- маршрут;
- файлы frontend и backend;
- связанные таблицы или модели;
- что работает фактически;
- какие ограничения или заглушки обнаружены.

Отдельно ответь:
- есть ли уже Console под старым названием;
- нужно ли переносить существующий интерфейс или создавать недостающее;
- есть ли две разные админки с дублирующим функционалом;
- какие проверки доступа действительно выполняются на сервере.

Не создавай пользователей, не сбрасывай базу,
не меняй права и не выводи пароли или токены.

В конце дай конкретный список недостающих работ.
