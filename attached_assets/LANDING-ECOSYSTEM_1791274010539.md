# Обновление лендинга — 29 сентября 2026

Лендинг `/` обновлён по продуктовой структуре Vernatun OS / HAYAT / ImTun. Сохранены React/Vite, текущая авторизация `/login`, существующие кабинеты, исходный логотип Vernatun и закрытые API. Схемы бизнес-данных не менялись.

## Изменения

- Навигация и порядок: первый экран → продукты → возможности → HAYAT → ImTun → четыре шага процесса → Vernatun OS и компактная приёмка → аудитории → подключение → FAQ → форма.
- Использованы оригинальные приложенные HAYAT и ImTun PNG, без цветовых фильтров и изменения пропорций. На тёмном фоне ImTun размещён на светлой поверхности.
- Новые секции и карточки: `src/components/Ecosystem.tsx`; структурированные данные и HY/RU/EN: `src/ecosystem-content.ts`; адаптивное оформление: `src/ecosystem.css`.
- Обновлены `App.tsx`, `content.ts`, Header, Shared, LeadFormSection, Previews, ResidentDemoDialog, `leadAdapter.ts`, `main.tsx`, SEO в `index.html`.
- Форма дополнена необязательной организацией, выбором продукта и аудитории; роль стала необязательной. CTA Vernatun OS выбирает продукт. Выбор аудитории не сбрасывает продукт. Согласие выключено по умолчанию, политика открывается существующим диалогом.
- Сохранены старые закладки #management, #residents, #modules, #contact; новые ссылки используют требуемые якоря.
- В демо явно обозначены демонстрационные данные; оплата не выполняется. Вкладки «Мой дом», «Платежи», «Заявки», Escape, удержание и возврат фокуса.

## Проверки

- TypeScript клиента и Vite build.
- `scripts/ecosystem-qa.cjs`: якоря, предварительный выбор продукта/аудитории, обязательные поля, неподключённая отправка без ложного успеха, FAQ, фокус/Escape демо, существующий вход, 360/390/768/1024/1440 px. Ошибок JavaScript не обнаружено.
- `scripts/landing-locales-qa.cjs`: HY по умолчанию, HY/RU/EN, отсутствие остаточного русского текста в HY/EN, пять ширин 320–1440 px.
- Новая бизнес-логика API не добавлялась; предыдущие серверные тесты для этого изменения не запускались.

## Приём лидов

Существующий `submitLead` не имеет серверного endpoint и ничего не передаёт/сохраняет. Поэтому подтверждённый сервером успех и ошибка настоящего endpoint не проверялись и не имитировались. Форма явно показывает ограничение. Для рабочего приёма нужны endpoint с валидацией и защитой от злоупотреблений, хранилище лидов, утверждённая политика обработки контактов и интерфейс/интеграция для их обработки. Поля `productInterest` и `audience` подготовлены в адаптере. Реальные письма/сообщения не отправлялись.

Внешняя аналитика не обнаружена; новые трекеры не подключены. Ссылок на магазины приложений, выдуманных контактов и production-публикации нет.

## Уточнение композиции по изображению

Повторно переработаны desktop-пропорции: компактные секции и форма, боковые превью продуктов, графики/строки задач, экран техника, три карточки заявок телефона, визуальные свидетельства четырёх шагов, логотипы в процессе и футере, архитектурные фоны. Используется HTML/CSS, а не изображение всей страницы. Воспроизведение приближено к референсу, но не подтверждено попиксельным сравнением: архитектурное фото и иллюстрации в мини-интерфейсах отличаются от исходного макета. Исходные фото мелких деталей и редактируемый дизайн-макет не предоставлены.
