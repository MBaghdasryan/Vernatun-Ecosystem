# Продуктовые порталы Vernatun

## Роли и стартовые страницы

| Роль | Продукт | Стартовая страница | Действия | Ограничения |
|---|---|---|---|---|
| platform_admin | Vernatun Console | /console/overview | Организации, подписки, внедрения, аудит | Нет автоматического доступа к финансам жителей |
| support | Vernatun Console | /console/onboarding | Внедрения, обращения, запрос временного доступа | Только назначенные работы и одобренные срочные разрешения |
| org_admin | Vernatun OS | /os/organization | Объекты, команда, приглашения, модули, настройки | Не получает финансовые права автоматически |
| portfolio_owner | Vernatun OS | /os/portfolio | Финансы, бюджеты, аренда, согласование расходов | Только назначенная область объектов |
| developer | Vernatun OS | /os/development | Дефекты, приёмка, осмотры, гарантии | Разрешённые объекты; отдельный исполнитель |
| accountant | Vernatun OS | /os/accounting | Начисления, платежи, корректировки, расходы | Опубликованные операции неизменяемы |
| manager | HAYAT | /hayat/management | Заявки, проверка работ, обслуживание, объявления | OS только с существующими финансовыми правами |
| dispatcher | HAYAT | /hayat/dispatch | Очередь, назначения, сообщения | Не получает финансовые права |
| technician | HAYAT | /hayat/my-work | Назначенные работы, чек-листы, отчёты, фото | Только свои разрешённые задания |
| contractor | HAYAT | /hayat/contractor | Назначенные дефекты и отчёты | Не принимает собственную работу |
| security | HAYAT | /hayat/security | Пропуска, события, инциденты | Нет фиктивного открытия двери |
| unit_owner | ImTun | /imtun/owner | Обязательства, заявки, показания, семья, пропуска | Только подтверждённое помещение и личные обязательства |
| renter | ImTun | /imtun/renter | Назначенные обязательства и сервисы | Нет полномочий собственника |
| family | ImTun | /imtun/family | Заявки, объявления, разрешённые документы | Нет финансов и управления пользователями по умолчанию |

Параметры query и hash при совместимом переходе сохраняются. Параметр `view` поддерживается; `requestId` открывает доступную заявку с повторной проверкой API. Переходы выполняются клиентом после проверки текущего назначения; чужой маршрут роли не выбирает роль автоматически. Внешние returnUrl не принимаются.

## Реализация

- `shared/products.ts`: единое сопоставление 14 ролей, четырёх продуктов, маршрутов и разделов. Не является механизмом авторизации.
- `server/access.ts`: каждый контекст возвращает основной/доступные продукты, стартовый маршрут и включённые модули. Прежние permissions, shell и ID сохранены.
- `src/portal/Portal.tsx`: продуктовые бренды, навигация, безопасный переключатель конкретных назначений, совместимые переходы. На время переключения экран размонтируется; следующий экран получает новый ключ назначения/продукта.
- `src/portal/product-i18n.ts`, `types.ts`, `portal.css`: HY/RU/EN, типы и адаптивные оболочки.
- `Workflow.tsx`: поддержка ссылки с requestId.
- `server/tests/security.test.ts`, `scripts/products-qa.cjs`: проверки продуктов и совместимости.

## Данные и миграции

SQL-миграции не понадобились. Пользователи, role IDs, назначения, бизнес-записи и cookie-сессии не копировались и не переименовывались. Переключение продукта не добавляет permissions. У управляющего тот же контекст HAYAT/OS; организация и область объектов неизменны. Console недоступна клиентским назначениям. При отключении finance вторичный OS управляющего исчезает.

Откат интерфейсного обновления: вернуть прежние Portal/Workflow/CSS и удалить продуктовые метаданные из access.ts. Откат БД не требуется.

## Границы

Перенесены существующие рабочие экраны и действия; это не реализация всех отсутствовавших бизнес-модулей из большого исходного задания. Расписание/материалы, полная банковская сверка, промышленные интеграции и окончательное визуальное соответствие 14 макетам остаются отдельными задачами (IMPLEMENTATION.md). Дополнительные demo-пользователи с совмещением сотрудника/жителя и двух организаций не создавались; существующие аккаунты сохранены. Переключатель показывает конкретные назначения, включая организацию и роль, без объединения полномочий.

Preview: http://localhost:5173/login. После входа открывается назначенный продукт; при нескольких назначениях предлагается выбор контекста.

## Проверки этого обновления

- 32 API-теста прошли: 19 безопасности/продуктов, 1 полного процесса заявок, 6 бизнес-сценариев, 4 сервисных, 2 приёмки/фото.
- В Chrome проверены 14 стартовых страниц и 113 доступных разделов; старые маршруты сохраняют параметры; переключение управляющего HAYAT ↔ OS не меняет permissions; клиентский администратор не открывает Console и получает 403 от API организаций.
- 360, 390, 768, 1024, 1440 px: нет горизонтального переполнения на проверенных стартовых страницах. Frontend/backend TypeScript и Vite build прошли.
- Отдельная имитация потери связи/гонок нескольких вкладок и исчерпывающая проверка каждого исторического формата deep link не выполнялись. Реализованы сохранение query/hash и открытие заявки по requestId.
